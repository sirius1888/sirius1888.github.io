# Sergei Karukes — portfolio

Портфолио для Senior / Lead React Native позиций. Адрес GitHub Pages — **https://sirius1888.github.io/**.

## Запуск

Нужен Node.js 22.13+; версия проекта указана в `.nvmrc`.

```sh
nvm use
npm ci
npm run dev
```

Разработка: **http://127.0.0.1:5173/**. Сервер слушает только локальный интерфейс; при занятом порте сообщает об ошибке.

```sh
npm test
npm run typecheck
npm run format:check
npm run build
npm run preview -- --port 4173 --strictPort
```

Готовая сборка: **http://127.0.0.1:4173/**. Результат сборки — `dist/`: статические HTML, CSS, JavaScript, шрифты и изображения. Серверная часть и секреты не нужны. `.npmrc` фиксирует `legacy-peer-deps` для совместной установки инструментов Sites и Vite; lockfile включён.

## Структура версии 2

1. **Профиль на весь первый раздел.** Имя, крупная фотография, специализация, весь стек с иконками без скрытых групп, контакты и CV. На мобильном раздел естественно становится длиннее одного экрана.
2. **Vinteo — текущая работа и лидерство.** Два разработчика, два тестировщика и PM, помимо Сергея. Agile, daily/demo, Git, документация, тестирование и монорепозиторий.
3. **Vinteo Mobile.** Отдельный iPhone с тёмно-синим интерфейсом и четырьмя сценариями: чат, iOS PiP, просмотр без камеры/микрофона, переподключение. Работают локальные сообщения, управление камерой/микрофоном, завершение и повторное подключение.
4. **Muse Group — Advertising Department.** Переиспользуемый рекламный модуль для Ultimate Guitar и MuseScore. Отдельная интерактивная схема SDK, адаптеров, аналитики и экспериментов.
5. **Примеры рекламы.** Второй iPhone переключается между Ultimate Guitar и MuseScore. Баннер, native, interstitial, rewarded; смена SDK и адаптера связана с архитектурной схемой. Consent можно дать и отозвать. Rewarded-сценарий требует завершения четырёхсекундной симуляции; закрытие, смена приложения/формата и отзыв согласия отменяют незавершённый просмотр.
6. **Ранний опыт.** «Мой О!» только текстом; затем Inobi, TimelySoft и CS-Soft. Контакты завершают страницу.

EN и тёмная тема — по умолчанию. Выбор EN/RU и темы сохраняется; смена настроек не сбрасывает демонстрации. Основное содержимое предварительно рендерится в HTML, затем React подключает взаимодействия. Контакты, опыт, весь стек и CV доступны без JavaScript. Учтены клавиатура, Escape и reduced motion.

Демонстрации — упрощённые реконструкции. Реальные звонки, рекламные SDK и трекеры не подключаются. SDK-переключатели иллюстрируют конфигурацию, а не смену нативного SDK в запущенном приложении. Музыкальный интерфейс показывает контекст рекламного размещения; авторство музыкальных функций пользователю не приписывается.

## Исходники

- `src/App.tsx` — последовательные главы, локализация, предпочтения и общий рекламный конфиг.
- `src/components/Profile.tsx` — первый экран, весь стек и иконки.
- `src/components/Phone.tsx` — общая рамка iPhone и конференционные сцены.
- `src/components/Advertising.tsx` — схема рекламного модуля и четыре формата для двух приложений.
- `src/content.ts` — технологии, справочные факты и ранний опыт.
- `src/styles.css` — основы, рамка телефона, Vinteo, навигация и контакты.
- `src/redesign.css` — композиция профиля, главы работодателей и рекламные примеры.
- `src/App.test.tsx` — проверки пользовательских сценариев и гидратации.
- `src/entry-server.tsx`, `scripts/prerender.mjs` — статический HTML.
- `public/cv/` — неизменённые копии двух исходных резюме.
- `.github/workflows/deploy.yml` — проверки, сборка и публикация на GitHub Pages.

Создан через Sites initializer и адаптирован под React + TypeScript + Vite и статическую сборку для GitHub Pages. `.openai/hosting.json` сохранён; внешних баз данных нет.

## Публикация и обновления

Репозиторий: `sirius1888/sirius1888.github.io`. В Settings → Pages источником публикации должен быть выбран **GitHub Actions**.

После push в `main` workflow проверяет форматирование, запускает тесты, собирает статический HTML и публикует `dist/`. Можно также запустить **Publish portfolio** вручную через Actions. Ветки с незавершённой работой не публикуются автоматически.

Перед обновлением выполните команды проверки из раздела «Запуск». После публикации проверьте публичную страницу, переключатели, контакты и оба CV.

PDF пока сохранены в исходном виде: в них осталось описание незавершённой кроссплатформенной архитектуры Vinteo и прежнего состава команды. Текст сайта следует уточнениям пользователя; редактирование самих резюме — отдельная задача.
